## Resume

Cette MEP ajoute le socle compte utilisateur dans l'application.
Elle introduit un bouton de connexion dans l'en-tete, une page de connexion, un parcours email + OTP, les entrees de social login, et une page profil editable.
Le parcours conserve la page d'origine de l'utilisateur pour pouvoir le rediriger apres connexion ou completion du profil.
La page profil affiche aussi une indication de completion afin d'encourager l'utilisateur a renseigner les informations manquantes.
Storybook est mis a jour pour couvrir les nouveaux etats d'authentification et le composant de profil.

## Changements inclus

- Navigation et entree de compte
  - Ajout d'un bouton de connexion dans la barre de menu, apres le lien actualite.
  - Integration du bouton dans la charte graphique existante.
  - Propagation de l'etat utilisateur au layout pour afficher les bons etats d'interface.

- Connexion et creation de compte
  - Ajout d'une page `/login`.
  - Ajout du flow email + OTP pour demander et verifier un code de connexion.
  - Ajout des entrees de social login pour les fournisseurs prevus.
  - Correction du formulaire SvelteKit pour utiliser une action nommee compatible avec les named actions.
  - Ajout d'une route localisee `/[lang]/login`.

- Redirection apres authentification
  - Ajout d'un helper serveur pour securiser et conserver l'URL de retour.
  - Redirection possible vers la page d'origine apres connexion ou apres passage par le profil.

- Profil utilisateur
  - Ajout d'un service serveur de profil utilisateur.
  - Ajout d'une page profil editable avec nom, prenom, date de naissance, email, adresse, pseudo, photo de profil et avatar.
  - Ajout d'un indicateur de completion du profil.
  - Nettoyage de la logique de role/authentification cote profil.

- Storybook et composants
  - Extraction d'un composant `ProfileAccount`.
  - Ajout des stories `ProfileAccount`.
  - Ajout des stories `AppHeader` pour les etats de connexion.

## Impact technique

- Prisma
  - La base doit contenir les tables liees aux utilisateurs et au flow OTP avant test du login.
  - En local, lancer les migrations Prisma si l'erreur `The table public.User does not exist` apparait.

- Authentification
  - Le flow email + OTP depend de la configuration serveur existante pour generer et verifier les codes.
  - Les social logins affichent les entrees prevues dans l'interface ; chaque fournisseur doit avoir sa configuration OAuth valide avant utilisation en production.

- Internationalisation
  - La route `/[lang]/login` est couverte pour eviter les erreurs 404 sur les URLs localisees.

- Risques connus
  - Verifier manuellement la connexion email + OTP sur une base migree.
  - Verifier chaque provider social active avec ses variables d'environnement de production.
  - Verifier le retour vers la page d'origine apres connexion depuis une page publique.
